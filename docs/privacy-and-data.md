# 개인정보·회의 데이터 정책

## 처리 범위

Good Listener는 회의 참가자의 음성, 전사, 참석자가 입력한 회의 문맥, 공개 웹 팩트 검색어와 출처, 진행 상태, 결정·할 일 후보, 최종 회의록을 처리한다.

음성은 브라우저에서 OpenAI Realtime API로 전송된다. 확정 전사와 필요한 최근 문맥은 진행 분석과 회의록 생성에 사용된다. 검증 가능한 주장에는 OpenAI의 공개 웹 검색 기능이 사용되므로 주장과 필요한 최소 문맥이 외부로 전송될 수 있다. 일반 `OPENAI_API_KEY`는 로컬 서버 밖이나 브라우저로 전달되지 않는다.

## 동의 원칙

- 마이크 권한 요청 전에 처리 목적, OpenAI 전송, 공개 웹 검색, 로컬 영구 보존을 한 화면에서 설명한다.
- 운영자는 모든 참가자의 명시적 동의를 확인해야 시작할 수 있다.
- 녹음·전사 중임을 회의 내내 화면에 표시한다.
- 동의를 철회하면 신규 음성 전송을 즉시 중단하고, 이미 저장된 회의의 보존 또는 삭제를 선택하게 한다.

## 로컬 보존과 암호화

- 자동 만료나 자동 삭제는 하지 않는다. 회의 데이터는 명시적으로 삭제할 때까지 로컬에 영구 보존한다.
- 연결 복구용 MediaRecorder 청크는 서버 ACK 전까지 브라우저 IndexedDB에 평문 Blob으로 임시 보존된다. 서버가 AES-GCM 암호화 저장을 확인하면 해당 브라우저 청크를 삭제하지만, 업로드 실패나 비정상 종료 시에는 다음 복구 시도까지 남을 수 있다.

로컬의 영구 보존 정책과 OpenAI 측 보존은 서로 다른 경계다. OpenAI는 API로 전송된 비즈니스 데이터를 기본적으로 모델 학습에 사용하지 않는다. 기본 abuse-monitoring 로그는 통상 최대 30일 보존되지만 법적 의무나 서비스·제3자 보호 필요가 있으면 더 길어질 수 있다. 별도 승인이 필요한 Zero Data Retention 또는 Modified Abuse Monitoring도 적용 endpoint와 Safety Retention 예외를 확인해야 한다. 실제 조직 설정을 참가자 고지와 사내 개인정보 검토에 포함하고, 최신 조건은 [OpenAI API 데이터 제어 문서](https://developers.openai.com/api/docs/guides/your-data)를 기준으로 확인한다.

- SQLite의 내용 필드와 복구용 음성은 master key로 암호화하고, Windows에서는 master key를 현재 사용자 DPAPI로 보호한다. 식별자, 상태, 시각, 파일 크기·경로 같은 운영 메타데이터는 평문이므로 데이터 폴더 접근 권한도 제한한다.
- 기본 저장 위치는 `%LOCALAPPDATA%\GoodListener\data`다.
- 앱 제거는 데이터 삭제 동의로 간주하지 않으며 uninstall 뒤에도 데이터와 key를 남긴다.
- IndexedDB 평문 대기열 때문에 전용 Windows 계정과 접근 제한된 브라우저 프로필을 사용해야 한다. 공용 계정·공유 프로필·브라우저 프로필 동기화를 운영 경계로 사용하지 않는다.

## 접근과 삭제

- v1은 회의실 Windows PC 한 대와 해당 Windows 사용자 계정만을 신뢰 경계로 삼는다.
- 서버는 loopback에서만 열고 다른 PC에 공유하지 않는다.
- 회의별 명시 삭제는 DB 레코드와 연결된 음성, 전사, 분석, 회의록을 함께 제거한다.
- 전체 삭제는 관리자 확인 후 데이터 디렉터리만 정확히 삭제한다. 자세한 절차는 `docs/operations.md`를 따른다.

## 로그 최소화

운영 로그에는 비밀키, client secret, 원문 음성, 전사·회의록 전문을 기록하지 않는다. 장애 조사에는 회의·요청 식별자, 상태 전이, 지연, 오류 종류, 사용량처럼 내용이 아닌 메타데이터만 사용한다.

이 정책은 제품의 기술 기본값이다. 실제 사내 운영자는 회사의 녹음 동의, 개인정보, 영업비밀, 보존 및 삭제 규정과 충돌하지 않는지 배포 전에 확인해야 한다.
