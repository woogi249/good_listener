# DR-04: 데이터 흐름 경계 / 개인정보 범위

**상태:** 작업 가설 (Phase 0 spike 전)
**작성일:** 2026-04-19
**선행 조건:** DR-01 (CLI 동시 호출 모델), DR-03 (STT 로컬 처리)

---

## 1. 가정 (Assumption)

- DR-01에서 CLI subprocess 동시 최대 2개 + 우선순위 큐 모델이 확정되었음을 전제로 한다.
- DR-03에서 Python 백엔드 + faster-whisper 로컬 처리가 확정되었음을 전제로 한다. 원본 오디오는 로컬 메모리 내에서만 처리되며 외부 STT API로 전송되지 않는다.
- **참여자 동의 절차 (한국 개인정보보호법 §15·§22 준수, CONSISTENCY.md S-2)**: 회의 시작 전 앱 UI에서 참여자 전원에게 동의 화면을 표시한다. 고지 항목: (1) 수집 데이터(음성→텍스트 변환 + AI 분석 송신), (2) 수집 목적, (3) 보유 기간(세션 종료 시 폐기, 사용자 "저장" 선택 시만 로컬 파일), (4) 거부 권리 및 거부 시 영향. **참여자 1인이라도 미동의 시 "전체 로컬 전용 모드"로 자동 진입**하여 CLI 분석을 비활성화하고 트랜스크립트 기록만 수행한다. 동의 기록(타임스탬프·동의/거부 여부)은 세션 메타데이터로 **로컬 보관**하여 감사 추적 가능. 이 절차는 **Phase 1 범위 내 구현**이며 Phase 2 연기 금지.
- 민감 정보 범위는 한국 개인정보보호법 기준을 따른다: 주민등록번호, 전화번호, 계좌번호, 의료정보, 그리고 외부 공개 불가 직장 내부 기밀(미공개 재무 수치, 고객 개인정보 등).
- 의존성: DR-01 (CLI 데이터 전송 경로 확정), DR-03 (STT 데이터 흐름 확정). 이 DR의 결론은 DR-05 (트리거 설계 — 어떤 발화를 CLI로 전송할지), DR-06 (UI — 로컬 전용 상태 표시)에 직접 영향을 준다.

## 2. 작업 가설 (Working Hypothesis)

**이중 경계(dual boundary) 설계**: 절대 로컬 전용 영역과 CLI 전송 허용 영역을 화이트리스트로 명시한다.

**Local-only 영역 (외부 전송 절대 금지)**
- 원본 오디오 스트림
- 전체 회의 트랜스크립트 (세션 누적 전체)
- 사용자 식별자, 참여자 메타데이터
- 세션 ID 및 앱 사용 로그

**CLI 전송 허용 영역 (화이트리스트)**
- 롤링 버퍼 직전 10~20발화 텍스트 (STT 변환 결과만, 원본 오디오 아님)
- 패널별 프롬프트 템플릿 (A/B/C/D-3 지시문)
- 트리거 컨텍스트 50자 이내 요약 (패널 출력 결과 재활용 시)

**세션 종료 정책**: 기본값은 모든 로컬 데이터 즉시 폐기(휘발성). 사용자가 회의 종료 시 명시적으로 "저장" 버튼을 눌렀을 때만 로컬 파일로 저장 허용. 로컬 저장 데이터도 외부 전송은 없음.

**민감정보 필터 (Phase 1 경량 + Phase 2 고급, CONSISTENCY.md S-6)**:
- Phase 1: **정규식 기반 경량 PII 필터** (주민등록번호 `\d{6}-\d{7}`, 전화번호 `\d{3}-\d{3,4}-\d{4}`, 계좌번호 패턴)를 즉시 구현. 레이턴시 영향 < 1ms로 STT 예산에 무시 가능. 감지 시 해당 발화를 롤링 버퍼에서 마스킹(`[REDACTED]`) 처리.
- Phase 2: NER 기반 고급 필터(이름·주소·조직명)를 측정 후 추가. DR-03과 공동 예산 재배분 협상.

**Phase 0 Spike 측정 데이터 보관 정책 (CONSISTENCY.md S-4)**:
- 실제 회의 음성은 최후 수단. 우선 **합성 음성·대본 낭독·모의 회의**로 측정 (DR-03 샘플 확보 계획 준용).
- 실제 음성 사용 시: 참여자 전원 동의 필수, **측정 완료 후 30일 이내 폐기**, 원본 오디오 저장소 커밋 금지(`.gitignore`), 결과 리포트는 통계값만 포함.
- CLI 호출 stderr·stdout 로그에 프롬프트 텍스트가 섞일 수 있으므로 **로그 파일도 30일 폐기 대상**. GitHub/공용 저장소 업로드 금지.

**제3자 데이터 처리 추적 (CONSISTENCY.md S-5)**:
- Anthropic CLI 통한 데이터 전송은 제3자 처리에 해당. DR-00b 통과 시 Anthropic의 데이터 보존·학습 사용 정책을 확인하여 `docs/decisions/third-party-processing.md`에 기록 (사용자 확인 항목, Phase 0 범위).

**화이트리스트 보강 카테고리 (CONSISTENCY.md S-7)**:
- 회의 참석자 이름·직책·소속, 회의실 이름, 타임스탬프/발화 순서, 패널 출력 이력 등 **롤링 버퍼 텍스트 내 자연 포함되는 간접 식별 정보**도 CLI 전송 대상이 됨을 명시. Phase 1 블랙리스트 훅에서 선택적 마스킹 가능하도록 설계.

## 3. 이유 (Rationale)

**보안 경계를 DR-05 이전에 확정하는 이유**

DR-05 트리거 설계는 "어떤 발화를, 언제, 어떤 형태로 CLI에 보낼지"를 결정한다. 그 결정이 내려지기 전에 "보낼 수 있는 데이터 카테고리"가 화이트리스트로 존재하지 않으면, 트리거 설계자가 임의로 데이터 범위를 정하게 된다. 보안은 사후 땜빵이 가장 비용이 크며, DR-05 설계 이후에 경계를 좁히면 트리거 로직 재작성이 불가피하다.

**롤링 버퍼만 전송하는 이유**

AGENTS.md CLI 호출 규약(125행)과 CLAUDE.md 롤링 버퍼 원칙이 이미 "전체 회의 기록 전송 금지"를 명시하고 있다. 이 DR은 그 원칙을 보안 결정으로 공식화한다. 롤링 버퍼 한정 전송은 토큰 비용, 프롬프트 누출 리스크, rate limit 부담을 동시에 줄인다.

**Phase 1 민감정보 필터 연기 근거**

완전한 PII 필터(정규식 + NER)는 STT 파이프라인에 추가 레이턴시를 유발한다. Phase 0 spike에서 STT 지연 예산이 이미 빠듯하게 설정되어 있으므로(DR-03 STT ≤ 3초), Phase 1에서는 훅 진입점만 확보하고 Phase 2에서 측정 기반으로 도입한다. 단, 훅이 존재하므로 Phase 2 도입 시 인터페이스 변경 없이 필터 로직만 삽입 가능하다.

## 4. 검증 방법 (Verification) — 체크리스트 + 매트릭스

숫자 강제 예외 DR. 이진 체크 항목과 데이터 흐름 매트릭스로 검증한다.

**데이터 흐름 매트릭스**

| 데이터 종류 | 로컬 저장 | CLI 전송 | WebSocket(브라우저) | 비고 |
|------------|-----------|----------|---------------------|------|
| 원본 오디오 스트림 | 세션 중 메모리만 | ❌ | ❌ | 세션 종료 즉시 폐기 |
| 전체 트랜스크립트 | 옵션 (기본 OFF) | ❌ | ❌ | 사용자 "저장" 선택 시만 로컬 파일 |
| 롤링 버퍼 (10~20발화) | 메모리만 | ✅ | ❌ | 화이트리스트. STT 변환 텍스트만 |
| 패널 출력 (50자) | 메모리만 | (결과 수신) | ✅ | 브라우저 표시용 |
| 사용자 식별자 / 메타데이터 | ❌ | ❌ | ❌ | 익명 세션. 수집 자체 없음 |

**감사 체크리스트** (Phase 0 spike에서 확인)

- [ ] 앱 실행 중 아웃바운드 HTTP/HTTPS 요청이 Anthropic 엔드포인트(`api.anthropic.com`) 외에 0건임을 netstat 또는 Wireshark 캡처로 확인
- [ ] 세션 종료 후 디스크에 오디오 및 트랜스크립트 파일 잔존 없음 (사용자 "저장" 미선택 시)
- [ ] CLI 프롬프트 로그 점검: 롤링 버퍼 텍스트 외 데이터(전체 트랜스크립트, 사용자 식별자) 미포함 확인
- [ ] 민감정보 블랙리스트 훅 진입점이 코드 내 존재함 (빈 함수라도 무방, Phase 2 구현 예약 확인)
- [ ] WebSocket 페이로드 덤프: 4패널 출력 텍스트(50자)만 포함되고, 원본 발화 텍스트가 미포함임을 확인
- [ ] 앱 종료 시 CLI subprocess 좀비 프로세스 0개 (ps aux 또는 tasklist로 확인)
- [ ] 참여자 동의 UI가 회의 시작 전 반드시 표시되며, 1인 미동의 시 "전체 로컬 전용 모드"로 자동 전환됨 (S-2)
- [ ] CLI 호출이 `claude -p "<프롬프트>"` 명령줄 인자 방식이 아닌 **stdin pipe** 방식임을 `ps aux`/`tasklist /v`로 확인 (프롬프트가 프로세스 목록에 노출되지 않음, S-1)
- [ ] Phase 0 spike 측정 데이터(오디오·로그) 30일 폐기 정책이 문서화되어 있으며 `.gitignore`에 관련 경로 포함됨 (S-4)

**통과 기준**: 체크리스트 9/9 통과. 1건 이상 실패 시 재설계 후 재검증.

## 5. 탈락 시 대안 (Fallback)

**아웃바운드 요청 누출 발견 시**
- 코드 추적으로 유출 지점을 특정하고 필터 또는 방화벽 규칙을 삽입한다.
- 유출이 CLI subprocess 내부 동작에 기인하는 경우, `claude` CLI 버전 업데이트 여부 확인 후 Anthropic 문의.

**세션 종료 후 잔존 디스크 데이터 발견 시**
- 세션 종료 훅에 안전 삭제(Python `os.unlink` + 덮어쓰기, 또는 `shred` 명령) 로직을 추가한다.

**민감정보가 롤링 버퍼에 유입될 위험이 Phase 1에서도 현실화될 경우**
- Phase 2로 연기했던 블랙리스트 필터를 Phase 1로 앞당긴다.
- 정규식 기반 PII 패턴(주민등록번호, 전화번호, 계좌번호 형식)을 STT 후처리 단계에 삽입, STT 레이턴시 영향을 재측정 후 DR-03과 공동으로 예산 재배분 협상.

**외부 참여자(고객사, 외부 업체 포함) 회의에서 앱을 사용하는 경우**
- 추가 동의 UI를 제공하고, 해당 세션은 롤링 버퍼 전송을 기본 차단("전체 로컬 전용 모드")으로 설정한다.
- 전체 로컬 전용 모드에서는 CLI 패널 분석을 비활성화하고 트랜스크립트 기록만 수행한다.

**영향받는 DR**
- **DR-05 (트리거 설계)**: 트리거가 CLI로 보내는 발화는 이 DR의 화이트리스트(롤링 버퍼 텍스트) 내로 제한되어야 함. DR-05에서 추가 데이터 카테고리 전송이 필요한 경우 이 DR 재검토 필요.
- **DR-06 (UI 설계)**: UI에 "로컬 전용 처리 중" 상태 표시를 의무화한다. 전체 로컬 전용 모드 진입 시 패널 비활성화 상태도 UI에 명시해야 함.
