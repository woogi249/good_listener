# DR-00a: 사용자 수요 검증

## 1. 가정 (Assumption)

- 대상 팀은 주 1회 이상 정기 회의를 갖는다
- 현재는 AI 보조 없이 회의를 진행 중이다
- 팀 공용 디스플레이(TV/모니터)가 회의실에 존재한다
- 팀원은 회의 중 정보 누락, 잘못된 전제, 교착 상황 등 불편을 경험한 적이 있다
- 의존성: 없음 (최상위 선행 DR, DR-01~06 모두 이 DR 통과 후 진행 가능)

## 2. 작업 가설 (Working Hypothesis)

3~5명 대상 30분 반구조화 인터뷰로 4패널 UI 목업을 보여주며 "이 앱을 실제 회의에서 쓰겠는가"를 확인한다. 최소 **3/5 이상 Yes(≥ 60%)** 면 수요 충분으로 판정하여 DR-01로 진행한다.

이 가설은 Phase 0 인터뷰 결과로 확정 또는 기각되며, 확정 전까지는 어떤 기술 검증(DR-01~06)도 착수하지 않는다.

## 3. 이유 (Rationale)

기술 불확실성 6건(CLI 레이턴시, STT 정확도, 트리거 조건 등)을 전부 해소하는 데 드는 공수는 수요 인터뷰 3~5건보다 최소 10배 이상 크다. 기술 검증을 먼저 완료해도 대상 팀이 앱을 쓰지 않으면 전체 투자가 0가치로 귀결된다.

실패 모드 분석:
- **기술 먼저, 수요 나중** 시나리오: STT 파이프라인과 CLI 디스패처를 구축한 뒤 인터뷰에서 "회의 중 화면을 보기 어색하다"는 반응이 나오면 아키텍처 전면 재설계 필요.
- **수요 먼저 검증** 시나리오: 인터뷰 3건(약 1.5시간)으로 프로젝트 방향을 결정. 탈락해도 손실 최소.

또한 4패널 구성(요약/팩트체크/아이디어/반박)의 우선순위는 실제 팀의 불편 지점과 일치할 때만 유효하다. 인터뷰는 패널 구성 자체의 타당성도 함께 검증한다.

## 4. 검증 방법 (Verification)

- **측정 도구**: 반구조화 인터뷰 + 4패널 정적 와이어프레임 1장 (실제 코드 아님, 목업 이미지만)
- **측정 횟수 (N)**: 3~5명 (팀 규모에 따라 조정; 소규모 팀이면 3명으로도 충분)
  > ⚠️ **통계 한계 인정 (CONSISTENCY.md C-5)**: N=3~5는 정량적 통계 검정(신뢰구간·유의성)이 불가능한 규모이다. 본 인터뷰는 **탐색적 정성 판단**을 목적으로 하며, 60% 기준은 go/no-go 의사결정의 **경험적 임계치**로만 활용한다. 통과해도 수요 확정이 아닌 "유의미한 1차 신호"로 해석하고, Phase 1 MVP 이후 추가 사용성 검증으로 보강.
- **대표값**: Yes 응답자 비율 (Yes / 전체 인터뷰 수)
- **환경 조건**: 인터뷰 대상자별 개별 1:1 세션, 각 30분, 실제 회의 경험 질문을 앞에 배치한 후 목업 제시
- **통과 기준**:
  - Yes ≥ 60% (3/5 또는 2/3 이상) → 수요 확인, DR-01 진행
  - Yes 40~60% (회색 영역) → "피벗 필요" 판정, 축소판 검토
  - Yes < 40% → 강한 거부, 프로젝트 전면 재검토

**인터뷰 질문 초안 (5개)**:

1. 최근 회의에서 중요한 정보나 결정 사항이 누락되거나 흐지부지된 경험이 있으신가요? 어떤 상황이었나요?
2. 회의 중 누군가의 발언이 사실과 다르다고 느꼈을 때, 직접 지적하기 어려웠던 경험이 있으신가요?
3. 회의가 같은 주제를 반복하거나 결론 없이 길어질 때 어떻게 대응하셨나요?
4. 회의 후 실행 항목이나 결정 사항을 정리하는 데 얼마나 시간이 걸리며, 그 과정에서 어떤 어려움이 있었나요?
5. (목업 제시 후) 이 4개 패널이 실시간으로 화면에 표시된다면, 실제 회의에서 켜 두겠습니까? 어색하거나 방해가 될 것 같은 요소가 있다면 무엇인가요?

**와이어프레임 요구사항**: 4패널(요약 / 팩트체크 / 아이디어 / 반박) 정적 이미지 1장. 각 패널에 예시 출력 1줄씩 표시. 실제 코드 구현 아님, 인터뷰 시각 보조 자료로만 사용.

## 5. 탈락 시 대안 (Fallback)

- **Yes < 40% (강한 거부)**: 실시간 4패널 포맷 전면 재검토. 대안 포맷 탐색:
  - 회의 후 리포트만 (D-1 Action Item + D-2 Decision Log) — 실시간 패널 없이 사후 일괄 처리만 제공
  - 개인용 보조 도구 전환 (팀 공용 디스플레이 아닌 개인 노트북 화면)
  - 모든 하위 DR(DR-01~06) 착수 보류, 프로젝트 목적 재정의 필요

- **Yes 40~60% (애매한 수용)**: 패널 수 축소. A 패널(Summarizer) 하나만 먼저 검증하는 축소판 제안. 나머지 3개 패널은 Summarizer MVP 사용 후 추가 피드백으로 결정. DR-01~02(CLI 관련)만 선행 진행하고 DR-03~06은 축소판 결과 후 재판단.

- **Yes ≥ 60% (통과)**: DR-00b(rate limit), DR-00c(하드웨어) 병렬 진행 후 DR-01로 이동.

- **영향받는 DR**: DR-00a 탈락 시 DR-00b·DR-00c·DR-01~06 전체 재검토 필수. DR-00a는 최상위 선행 DR로, 이 결과 없이 하위 DR을 확정할 수 없다.
