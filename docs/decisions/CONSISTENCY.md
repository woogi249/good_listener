## 2. 양방향 정합성 체크리스트

각 항목은 "A의 가정 ↔ B의 산출" 형태로 양방향 일치를 확인한다.

- [ ] **[C-01]** DR-01 가정("DR-00b에서 시간당 60회 호출이 rate limit 에러 없이 통과") ↔ DR-00b 작업 가설("분당 1회, 총 60회 연속 호출 시 성공률 ≥ 95%") — **일치. DR-00b 통과 기준이 DR-01의 전제를 직접 공급함.**

- [ ] **[C-02]** DR-02 가정("DR-00b 60회/시간 허용 확인") ↔ DR-00b 통과 기준("성공률 ≥ 95% AND rate limit 에러 0회") — **일치. DR-02는 DR-00b 통과 확인 후에만 레이턴시 측정 의미를 가짐.**

- [ ] **[C-03]** DR-02 역산("STT 3초 + CLI 5초 + UI 1초 + 마진 0.9초 = 10초") ↔ DR-03 통과 기준("청크 레이턴시 p95 ≤ 3초 GPU / ≤ 5초 CPU") — **부분 일치. DR-02는 STT에 3초를 할당하고, DR-03은 GPU 경로에서 p95 ≤ 3초를 통과 기준으로 삼으므로 GPU 경로는 일치. 그러나 CPU 경로(p95 ≤ 5초)를 DR-03이 허용하면 DR-02의 10초 예산이 5+5+1+0.9 = 11.9초로 초과함. 실측 후 공동 재배분 확인 필요.**

- [ ] **[C-04]** DR-03 가정("DR-00c에서 확정된 하드웨어 프로파일 전제") ↔ DR-00c 산출("CPU/RAM/GPU/스토리지 스펙 확인 + `docs/decisions/hardware-profile.md` 별첨") — **일치. DR-00c가 hardware-profile.md를 산출하면 DR-03이 GPU/CPU 분기를 결정하는 구조로 연결됨.**

- [ ] **[C-05]** DR-04 가정("DR-01에서 CLI 동시 최대 2개 + 우선순위 큐 확정") ↔ DR-01 작업 가설("동시 최대 2개 CLI 프로세스 + 우선순위 큐 채택") — **일치. 단, DR-01이 Phase 0 실측에서 "완전 병렬 가능(4개 동시)" 판정으로 가설 강화될 경우, DR-04는 데이터 전송 경로를 재검토해야 함(전송 빈도 증가).**

- [ ] **[C-06]** DR-04 가정("DR-03에서 Python 백엔드 + faster-whisper 로컬 처리 확정") ↔ DR-03 작업 가설("faster-whisper + Python 백엔드 확정") — **일치. DR-03이 백엔드 언어를 Python으로 명시 확정하며, DR-04는 이를 전제로 오디오 외부 전송 불가 근거로 활용함.**

- [ ] **[C-07]** DR-05 가정("DR-02에서 CLI 왕복 p50 3초 / p95 5초 가설") ↔ DR-02 통과 기준("p50 ≤ 3초 AND p95 ≤ 5초") — **일치. DR-05 동적 쿨다운 공식 `max(30, 3×(STT_p95 + CLI_p95))`는 DR-02/DR-03 실측값을 변수로 사용하므로, 실측 전까지는 초기값 30초가 하한선으로 작동함. 실측 후 연동 확인 필요.**

- [ ] **[C-08]** DR-05 가정("DR-04 화이트리스트: 롤링 버퍼 텍스트만 CLI 전송 허용") ↔ DR-04 작업 가설("CLI 전송 허용 영역: 롤링 버퍼 직전 10~20발화 텍스트") — **일치. DR-05의 트리거 평가자(TF-IDF, NER, n-gram)가 모두 발화 텍스트만 소비하며 원본 오디오에 접근하지 않음을 DR-05 이유 섹션이 명시함.**

- [ ] **[C-09]** DR-06 가정("DR-03에서 STT 2~5초 청크 스트리밍 가능 전제") ↔ DR-03 작업 가설("VAD 2~5초 청크 + 스트리밍 부분 디코딩") — **일치. DR-06 자막 바는 DR-03의 청크 단위 출력을 직접 소비하는 구조.**

- [ ] **[C-10]** DR-06 가정("DR-05에서 분당 트리거 ≤ 2회 통과 전제 → 패널 갱신 30~60초 간격") ↔ DR-05 통과 기준("분당 전체 트리거 ≤ 2회") — **일치. DR-06의 갱신 주기 전제(30~60초)는 DR-05 쿨다운 하한선(30초)과 정합함. 단, DR-05 폭주 발생 시 DR-06의 정보 과부하 판정도 연쇄 영향받음.**

- [ ] **[C-11]** DR-05 가정("1시간 기준 CLI 총량 ≤ 40회, DR-00b 기준 60회의 67%") ↔ DR-00b 통과 기준("시간당 60회") — **일치. 단, DR-00b가 "회색 영역(51~56회 성공)"으로 판정되어 쿨다운 60초 이상으로 상향 시, DR-05 초기 쿨다운 공식 결과가 달라지므로 DR-05 파라미터 재조정 필요.**

- [ ] **[C-12]** DR-01 의존성 선언("이 DR의 결론은 DR-05와 DR-02에 직접 영향") ↔ DR-05 선행 조건("DR-01 동시성 모델 확정 전 DR-05 작성 금지") — **일치. 합의안 실행 순서와 완전히 정합함.**

## 3. 감지된 모순 / 긴장

### [T-01] CPU-only 경로의 STT 지연 vs. DR-02 end-to-end 예산 초과
**심각도: HIGH**

DR-03은 CPU-only 경로에서 STT p95 ≤ 5초를 통과 기준으로 허용한다. DR-02의 10초 예산 배분에서 STT는 3초로 할당되어 있다. CPU 경로 채택 시 STT 5초 + CLI 5초 + UI 1초 + 마진 0.9초 = **11.9초**로 10초 목표를 초과한다.

**해소 방향:** DR-00c 하드웨어 확인 결과 GPU 없음 판정 시, DR-02와 DR-03이 공동으로 end-to-end 목표를 10초 → 13초로 완화하거나 CLI 예산을 3초로 단축하는 재배분 협상을 실시해야 한다. 어느 한 쪽만 수정하면 불일치가 유지된다.

**✅ 해소됨 (2026-04-19):** DR-02에 **CPU-only 경로 병렬 예산 테이블**이 추가되어 end-to-end 상한이 GPU=10s / CPU=12s로 양분되었다. DR-03 Fallback과 일치하며, 12s 초과 시 DR-03 플랜 C 또는 DR-02 플랜 C로 이행하도록 트리거 조건이 명시됨.

---

### [T-02] DR-01 동시 4개 강화(Fallback) vs. DR-04 데이터 전송 빈도
**심각도: MEDIUM**

DR-01 Fallback에서 "동시 4개 완전 병렬 가능" 판정이 나오면 우선순위 큐 없이 4개 패널이 독립 워커로 스폰된다. DR-04는 "CLI 전송 허용 영역: 롤링 버퍼 10~20발화"의 **빈도**를 제한하지 않으며, 전송 **내용** 화이트리스트만 정의한다. 4개 동시 스폰은 순간 버스트로 DR-00b rate limit 마진(60회 중 40회 사용 설계)을 압박할 수 있다.

**해소 방향:** DR-01 완전 병렬 결론 채택 시, DR-05 트리거 쿨다운을 재계산하여 시간당 총량이 60회를 초과하지 않음을 명시적으로 확인해야 한다.

**✅ 해소됨 (2026-04-19):** DR-01 "완전 병렬 가능 판정" Fallback에 **선행 게이트(필수)** 조항 추가. DR-00b를 순간 버스트 패턴(4개 동시 × 10분 = 40회)으로 재실행하여 성공률 ≥ 95% 확인 전까지 경로 진입 금지. 추가로 DR-05의 `rate_limit_headroom` 계수 재계산 의무 명시.

---

### [T-03] DR-05 쿨다운 공식 하한선 30초 vs. DR-00b 회색 영역 대응
**심각도: MEDIUM**

DR-05 동적 쿨다운 공식은 하한선 30초를 유지한다. 그러나 DR-00b 회색 영역(성공률 85~94%) 판정 시 쿨다운을 60초 이상으로 상향하라는 지침이 있다. 공식 `max(30, 3×(STT_p95+CLI_p95))`은 DR-02 가설(CLI 5초), DR-03 가설(STT 3초)을 대입하면 `max(30, 24) = 30초`로 하한선이 적용된다. DR-00b 회색 영역 시 공식이 자동으로 60초를 생성하지 않는다.

**해소 방향:** DR-00b 회색 영역 판정 시 쿨다운 공식의 하한선을 60초로 명시적으로 파라미터화해야 한다. `config/triggers.yaml`에 `cooldown_floor_seconds` 항목을 두고 DR-00b 결과에 따라 30 또는 60으로 설정하는 방식 권장.

**✅ 해소됨 (2026-04-19):** DR-05 공식이 `base × rate_limit_headroom` 구조로 개편됨. DR-00b 성공률에 따라 headroom 계수 1.0(통과) / 1.5(회색) / 2.0(탈락 근처)가 자동 적용되어, 회색 영역 시 쿨다운이 45초로 연장된다. 탈락 근처(< 85%)는 60초로 연장.

---

### [T-04] DR-06 50자 → 35자 Fallback vs. CLAUDE.md 상위 제약
**심각도: LOW**

DR-06 Fallback에서 "3m 거리 판독 실패 시 출력을 50자 → 35자로 축소"라는 경로가 있다. 이는 CLAUDE.md 최상위 제약("1줄/50자 엄수")과 직접 충돌한다. DR-06은 "CLAUDE.md 50자 제약의 예외 적용을 명시적으로 재협상해야 함"이라고 기술하나, 재협상 프로세스(누가, 언제, 어떤 방식으로)가 불명확하다.

**해소 방향:** DR-06 Fallback에 "사용자 명시적 승인 후에만 진행" 조건을 추가하고, CLAUDE.md 변경 시 DR-06도 함께 개정 스탬프를 받는 절차를 명시할 것.

**✅ 해소됨 (2026-04-19):** DR-06 Fallback에 **⚠️ 경고 블록** 추가. (1) 사용자 승인 필수 명시, (2) 대안 우선순위 3단계(글자 크기 승격 → TV/시야 권고 → 최후 35자 축소) 명시, (3) CONSISTENCY.md T-04 참조로 추적 가능.

## 4. 외부 가정 추적

각 DR이 프로젝트 외부 자원 또는 외부 사실에 의존하는 항목을 추적한다.

| 외부 가정 | 의존 DR | 현재 처리 방식 | 리스크 |
|----------|---------|--------------|--------|
| **Anthropic rate limit 정책** (분·시간당 정확한 수치 미공개) | DR-00b, DR-01, DR-05 | DR-00b에서 경험적 실측으로 파악. 공식 수치 없음을 명시함 | Anthropic 정책 변경 시 DR-00b 재실행 필요 |
| **faster-whisper 한국어 벤치마크 수치** (large-v3 WER 10~15% 공개값) | DR-00c, DR-03 | DR-03에서 공개 벤치마크를 초기 가정으로 사용하고 실측으로 재검증 계획 | 회의실 환경 WER이 공개값보다 높을 가능성 있음 (소음, 발화 겹침) |
| **회의실 PC 사양** (CPU/GPU/RAM) | DR-00c, DR-03, DR-05 | DR-00c에서 사용자가 직접 확인하는 구조. `hardware-profile.md` 산출물 | 확인 전까지 DR-03 모델 선택 미결. Phase 0 spike 착수 블로커 |
| **한국어 음성 샘플 가용성** (15분 × 3종 실환경 녹음) | DR-03, DR-05 | DR-03 검증 방법에서 샘플 3종 수집을 전제. 준비 여부 명시 없음 | 실환경 녹음 없이는 WER 실측 불가. Phase 0 spike 전 준비 필요 |
| **사용자(팀) 동의 범위** (앱 실행 및 음성 분석에 사전 동의) | DR-04 | DR-04 가정에서 사전 고지 및 동의 완료를 전제로만 기재. 동의 수집 절차 미정 | 외부 참여자 포함 회의 시 추가 동의 미비 가능성 (DR-04 Fallback에서 언급) |
| **Nielsen 10초 응답 시간 기준** | DR-02 | DR-02 이유 섹션에서 근거로 인용 | 학술 근거로 안정적이나, 회의 맥락에서 10초가 적합한지 실사용 검증 부재 |

## 6. Phase 0 Spike Readiness

### 통과 조건 점검

| 점검 항목 | 상태 | 비고 |
|----------|------|------|
| 9개 DR 모두 5섹션 구조 완비 | 통과 | 모든 파일 구조 확인 |
| DR 간 의존성 매트릭스 완성 | 통과 | 10건 의존 관계 추출 |
| 양방향 정합성 체크리스트 12건 작성 | 통과 | C-01~C-12 |
| 모순/긴장 감지 및 해소 방향 제시 | 통과 | T-01~T-04 (4건) |
| Acceptance Criteria 8/8 달성 | 통과 | AC7은 T-04 해소 조건부 |
| 외부 가정 추적표 작성 | 통과 | 6개 항목 |

### 재검토 필요 DR 목록

Phase 0 spike 착수 전 아래 항목을 해소해야 한다.

1. **DR-00c** — 회의실 PC 실제 스펙 확인 전까지 DR-03 착수 불가. `hardware-profile.md` 작성이 Phase 0 spike의 첫 번째 물리 액션.
2. **DR-03 + DR-02 공동** — CPU-only 경로 채택 시 end-to-end 10초 예산 초과 모순(T-01) 해소. 실측 전 GPU/CPU 분기 판정 불가.
3. **DR-05** — DR-00b 회색 영역 판정 시 `cooldown_floor_seconds` 파라미터를 `config/triggers.yaml`에 명시적으로 추가해야 T-03 해소.
4. **DR-06** — 3m 판독 실패 Fallback의 사용자 승인 프로세스를 T-04 지침에 따라 보완.

### 선언

위 재검토 항목 4건을 해소하고 C-01~C-12 체크리스트를 Phase 0 spike 실측 결과로 갱신하면, 본 9개 DR은 **Phase 0 spike 설계서로 즉시 활용 가능**하다. 의존성 순서는 `DR-00a·b·c (병렬) → DR-01·02·03 → DR-04 → DR-05 → DR-06` 이며, 이 순서가 spike 실행 계획의 기준 시퀀스가 된다.
