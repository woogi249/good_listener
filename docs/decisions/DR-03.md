# DR-03: STT 로컬 Whisper 한국어

**상태:** 작업 가설 (Phase 0 spike 전)
**작성일:** 2026-04-19
**선행 조건:** DR-00c (하드웨어 스펙 확정)

---

## 1. 가정 (Assumption)

- DR-00c에서 확정된 하드웨어 프로파일을 전제로 한다. GPU 6GB+ VRAM 경로와 CPU-only 경로는 이 DR 내에서 분기 처리한다.
- AGENTS.md의 Phase 0 통과 기준 "STT 지연 ≤ 3초"는 근거 없이 설정된 수치다. 이 DR의 검증 섹션에서 end-to-end 역산 기반으로 재정당화하거나 수정한다.
- 회의 환경: 2~5명 참여, 회의실 기본 마이크(단일 채널) 또는 USB 외장 마이크, 한국어 대화 (기술 용어·영어 혼재 가능). DR-00c 마이크 조건 그대로 계승한다.
- STT 결과물(트랜스크립트)은 롤링 버퍼로 유지되며, 패널 트리거의 입력 소스가 된다. 트리거 정확도(DR-05)는 이 DR의 WER 수치에 직접 의존한다.
- 백엔드 언어는 Python을 전제로 한다. faster-whisper가 Python 네이티브 바인딩이므로, Python 이외의 백엔드(Node.js 등)를 선택할 경우 이 DR의 도구 전제가 무효화된다. 백엔드 언어는 이 DR에서 Python으로 확정된다.
- 의존성: DR-00c (하드웨어). 이 DR의 결론은 DR-05(트리거 조건 정확도), DR-06(UI 신뢰도 표시), DR-02(end-to-end 레이턴시 재배분)에 영향을 준다.

## 2. 작업 가설 (Working Hypothesis)

**faster-whisper large-v3 + VAD(Voice Activity Detection) 2~5초 청크 + 스트리밍 부분 디코딩**. GPU 6GB+ VRAM 전제. 백엔드 언어: Python 확정(faster-whisper 네이티브).

- CPU-only 분기: medium 모델 + int8 양자화로 대체. WER 증가 허용, STT 지연 허용치를 3초 → 5초로 완화 재협상 필요.
- 화자 분리: Phase 1에서는 생략(최근 발화자 단일 표시). D-1 Action Item의 "누가" 품질이 기준 이하로 판명되면 Phase 2에서 pyannote-audio 도입 검토.

이 가설은 Phase 0 spike 측정 결과에 따라 확정 또는 기각된다.

## 3. 이유 (Rationale)

**WER 목표치 역산 근거**

트리거 정확도를 기준으로 허용 WER을 역산한다. Fact-Checker(패널 B)는 숫자·고유명사·기술 주장을 감지할 때 발동한다. 해당 키워드 범주에서 오인식률이 25%를 초과하면 허위 팩트체크(없는 수치를 감지하거나 실제 수치를 누락)가 유발된다. 따라서 회의실 환경 WER 허용 상한을 **≤ 25%**로 설정한다. 깨끗한 단일 발화 환경은 대조군 기준 **≤ 15%**를 통과 기준으로 둔다.

- large-v3 한국어 WER 공개 벤치마크: 깨끗한 녹음 10~15%, 회의실 잡음 환경 20~25%
- medium 모델 한국어 WER: 깨끗한 녹음 15~20%, 회의실 환경 25~35% (large-v3 대비 5~10%p 열위)

**faster-whisper 선택 이유**

CTranslate2 백엔드로 원본 OpenAI Whisper 대비 2~4배 빠른 추론 속도. int8 양자화 지원으로 VRAM/RAM 점유 축소. Python 네이티브이므로 FastAPI 백엔드와 동일 프로세스 내 통합 가능하며 IPC 오버헤드 없음.

**whisper.cpp 미선택 이유**

C++/Python(또는 Node.js) 바인딩 복잡도가 높고, 한국어 실환경 벤치마크 데이터가 부족하다. Python 백엔드 확정 시 ctypes 래핑이 필요해 유지보수 부담이 커진다.

**VAD 청크 크기 2~5초 근거**

2초 미만: 문장이 중간에 잘려 문맥 소실 → 트리거 오발동 증가. 5초 초과: 발화 종료 감지까지 추가 대기 발생, STT 지연이 3초 기준을 초과할 가능성 상승. 2~5초 범위는 한국어 평균 발화 단위(문장 1~2개)를 포괄하면서 실시간성을 확보한다.

**백엔드 언어 연쇄 효과**

faster-whisper를 선택하는 순간 백엔드는 Python으로 확정된다. Node.js 기반 백엔드로 전환하려면 whisper.cpp 또는 유료 STT API로 대체해야 하며, 이는 이 DR 전체를 재작성해야 하는 경로 의존성을 형성한다. 따라서 이 DR은 백엔드 언어를 Python으로 명시적으로 확정한다.

## 4. 검증 방법 (Verification)

- **측정 도구**:
  - Python 스크립트 + `faster-whisper` API (CTranslate2 백엔드)
  - WER 계산: `jiwer` 라이브러리 (`jiwer.wer(reference, hypothesis)`)
  - 한국어 특성상 CER(문자 오류율)도 병기: `jiwer.cer()`
  - RTF 측정: `time.perf_counter` (처리 시간 / 오디오 길이)
  - VAD 청크별 레이턴시: 청크 입력 시각 ~ 텍스트 출력 시각 차이
- **측정 횟수 (N)**: 샘플 3종 × 청크 수 합계 약 180개 (15분 오디오 × 3 / 평균 청크 5초)
- **대표값**: 청크별 레이턴시 p50 / p95, WER 및 CER (샘플 전체 평균)
- **테스트 샘플 (3종)**:
  1. 깨끗한 1인 녹음 (대조군) — 헤드셋 마이크, 무음 배경, 15분
  2. 3인 회의실 녹음 (타겟 환경) — 테이블 마이크, 에어컨 잡음, 15분
  3. 5인 회의 + 말겹침 포함 (극단 환경) — 동일 마이크, 2인 이상 동시 발화 구간 포함, 15분

- **샘플 확보 계획 (Phase 0 착수 블로커 해소, CONSISTENCY.md A-1)**:
  - **주체**: 사용자 + 내부 팀원. 실제 음성 사용 시 참여자 전원 사전 동의 필수 (DR-04 동의 절차 적용).
  - **샘플 1**: 사용자 본인이 기술 회의 모사 대본(숫자·고유명사 포함) 15분 낭독 녹음. 대조군 용도로 합성·낭독으로도 충분.
  - **샘플 2**: 실제 팀 회의 1회 녹음 (동의 획득 후) 또는 3인 모의 회의 15분 (시나리오 대본 제공).
  - **샘플 3**: 5인 모의 회의 15분. 시나리오로 의도적 발화 겹침 유도. 실제 회의 확보 어려우면 모의로 대체.
  - **수동 라벨(정답 트랜스크립트)**: Phase 0 착수 전 샘플 3종 모두 준비 완료. 라벨링은 2명 교차 검수 권장.
  - **준비 완료 기한**: Phase 0 spike 착수 전 (블로커).
  - **저장·폐기 (S-4 연계)**: 측정 완료 후 30일 이내 폐기. 원본 오디오는 저장소 커밋 금지(`.gitignore` 경로 등록). 분석 리포트에는 통계값만 포함 (원문·원본 오디오 제외).
- **환경 조건 (고정)**:
  - DR-00c에서 확정된 회의실 PC 사양 (GPU 경로: large-v3, CPU-only 경로: medium + int8)
  - 샘플링 레이트: 16kHz 단일 채널 WAV
  - 배경 소음 수준 측정 후 기록 (dB SPL)
  - faster-whisper beam_size=5, language="ko" 고정
- **통과 기준 (정량)**:

  | 조건 | 지표 | 기준 | 판정 |
  |------|------|------|------|
  | GPU (large-v3) | RTF | ≤ 0.3 | 통과 시 GPU 경로 확정 |
  | CPU-only (medium + int8) | RTF | ≤ 1.0 | 통과 시 CPU 경로 허용 |
  | 샘플 1 (깨끗한 1인) | WER | ≤ 15% | 대조군 기준선 |
  | 샘플 2 (3인 회의실) | WER | ≤ 25% | 타겟 환경 핵심 기준 |
  | 샘플 3 (5인 + 말겹침) | WER | ≤ 35% | 극단 환경 경고 허용 |
  | 청크 레이턴시 | p95 | ≤ 3초 (GPU) / ≤ 5초 (CPU) | end-to-end STT 구간 예산 충족 |

- **STT 구간 3초 근거 재정당화 (DR-02 역산 기반, CONSISTENCY.md C-1)**: DR-02의 end-to-end 목표 **10초** 예산에서 UI 렌더링(1초) + 마진(0.9초) + 트리거 판정(0.1초)을 제외한 **STT + CLI 합산 예산 = 8초 (= 10 − 1 − 0.9 − 0.1)**. 이를 STT 3초 + CLI 5초(DR-02 기준)로 배분한다. end-to-end 10초 자체의 근거는 DR-02 섹션 3 참조(Nielsen 응답시간 기준). 배분 성립하지 않으면 DR-02와 공동 재협상 필요.
- **수집 지표**: 오인식 단어 패턴 분류 (숫자 / 고유명사 / 기술 용어 / 일반 어휘 별도 집계), VAD 청크 경계에서 문장 절단 발생 빈도.

## 5. 탈락 시 대안 (Fallback)

**탈락 조건 A — WER > 25% (샘플 2, 회의실 녹음)**

- 플랜 A: faster-whisper large-v3-turbo 전환 시도 (추론 속도 향상, 정확도 유사 수준 보고됨, 실측 필요)
- 플랜 B: 후처리 룰 추가 — 숫자 정규화(예: "삼십 퍼센트" → "30%"), 도메인 용어 사전(프로젝트 고유 기술 용어 화이트리스트) 적용
- 플랜 C: 유료 STT 전환 (Clova Speech 또는 Google Speech-to-Text) — CLAUDE.md 비용 제약의 예외 처리를 사용자에게 명시적으로 요청. 전환 시 이 DR 전면 재작성 필요. **자격증명 관리 (CONSISTENCY.md S-3)**: 환경변수(`CLOVA_API_KEY` 또는 `GOOGLE_APPLICATION_CREDENTIALS` 경로)로만 관리, 하드코딩·저장소 포함 금지. DR-00b 플랜 B 키 관리 규약 준수.

**탈락 조건 B — RTF > 1.0 (CPU-only 경로에서도 실시간 불가)**

- 플랜 D: medium 모델 + int8 양자화 → small 모델로 추가 다운그레이드. WER 허용 범위를 DR-05(트리거 설계)와 공동으로 재협상.
- 플랜 E: 하드웨어 업그레이드 — GPU 추가 구매 (DR-00c 재확인, 예산 승인 필요). 구매 전 이 DR은 "보류" 상태 유지.

**탈락 조건 C — 화자 분리 필수 판명**

D-1 Action Item의 "누가/무엇을/언제까지" 품질 측정에서 발화자 귀속 오류가 30%를 초과하는 경우, pyannote-audio를 Phase 1에 앞당겨 도입한다. 추가 VRAM 소비(약 1~2GB) 및 RTF 증가를 재측정하여 통과 기준 재검토.

**영향받는 DR**

- **DR-02 (end-to-end 레이턴시)**: STT 구간 예산(3초)이 미달될 경우 CLI 구간과 공동으로 재배분 협상. 어느 한쪽이 초과하면 양쪽 동시 재작성.
- **DR-05 (트리거 조건 정확도)**: WER이 25%를 초과하면 키워드 기반 트리거(특히 Fact-Checker 수치 감지)의 신뢰도가 하락한다. WER 실측값을 DR-05 트리거 임계값 설계의 입력값으로 사용해야 하므로 이 DR 확정 전 DR-05 작성 금지.
- **DR-06 (UI 신뢰도 표시)**: WER 수치에 따라 패널 출력에 신뢰도 인디케이터(낮음/보통/높음) 표시 여부를 DR-06에서 결정해야 한다.
