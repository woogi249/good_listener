## 제품 방향

`good-listener`는 회의 후 회의록 생성기가 아니라, **회의 중 판단을 돕는 실시간 공용 화면**이다.

핵심 포지셔닝:

- 회의 중 놓치기 쉬운 요약, 검증, 반박, 고객 관점, 액션 후보를 즉시 분리한다.
- 대시보드에는 짧은 한 줄만 보여준다.
- 완료된 C+ 카드를 누르면 상세 근거와 다음 액션을 확인한다.
- 최근 발화 중심 롤링 버퍼로 프롬프트 범위를 줄인다.
- ggui와 EXAONE를 활용한 트랙 참여 권한을 전면에 둔다.

## 발표/심사 Q&A 주의점

사용자가 제시한 Q&A 초안에서 Q3의 다음 문장은 현재 구현보다 과하게 들릴 수 있다.

```text
회의 종료 후에는 Action Item과 Decision Log를 자동 생성해 후속 실행까지 이어지게 합니다.
```

현재 구현 기준으로는 실시간 `TODO 액션 후보`는 있으나, 회의 종료 후 사후 리포트 `Action Item / Decision Log`는 아직 로드맵이다.

권장 표현:

```text
대시보드에는 간결한 한 줄 인사이트를 보여주고, 완료된 카드를 누르면 상세 근거와 다음 액션을 확인할 수 있습니다.
```

또는:

```text
실시간으로 액션 후보와 결정 후보를 축적하고, 이후 Action Item과 Decision Log 리포트로 확장할 수 있습니다.
```

## 알려진 한계

1. Action Item / Decision Log 사후 일괄 리포트는 아직 완성 기능이 아니다.
2. 마이크 STT는 4초 청크 기반이다. VAD 기반 발화 경계 감지는 아직 없다.
3. 실제 EXAONE API 호출은 네트워크와 키 상태에 의존한다. 발표 시연은 fixture 모드가 안전하다.
4. fact-check의 실제 외부 근거 품질은 API/검색 결과에 의존한다. 데모 fixture는 안정성을 위해 고정 문구를 사용한다.
5. 민감정보 필터, 동의 화면, 로컬 전용 모드 정책은 아직 로드맵이다.
6. Electron/단일 실행 파일 패키징은 아직 없다.
7. 트리거 조건은 룰 기반이다. 실제 회의 로그로 false positive/false negative 튜닝이 필요하다.
